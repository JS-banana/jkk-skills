# Deep Memoir

像大脑在睡眠中巩固记忆：回顾近期各项目的对话，把值得留下的经验写成持久
记忆，把过时、重复、已被仓库正典覆盖的清掉。整个流程**报告先行**——
先给用户看整理报告，确认后才落盘。

## 硬性规则

1. 报告经用户确认前，不新增、不修改、不删除任何文件。
2. 只写 `~/.claude/projects/<project>/memory/`，且每条记忆写回其**来源项目
   自己的** memory 目录——公司项目与个人项目常同在一台机器，知识归属以
   项目为界，跨项目搬运（包括提炼「通用经验」写到别处）是事故。
3. **仓库正典优先**：项目仓库能记录的内容（AGENTS.md / CLAUDE.md、代码、
   git 历史）不进 memory；已有条目如今被正典覆盖的，列入拟删除。
   memory 只留正典装不下的三类：个人偏好与纠正、易变的进行状态、
   本机环境事实。
4. 保持各项目既有 memory 格式；每个 MEMORY.md 索引 ≤ 200 行。
5. 删除与合并在报告中逐条给出理由。

## Phase 1 — Orient（定向，产出：本次处理名单）

运行本 skill 目录下的采集脚本了解全局：

```bash
python3 scripts/gather.py --list --days 7
```

输出按活跃度排序：memory 文件数、近 N 天会话数、最后活跃日期，以及
`path` 列——项目在磁盘上的真实路径，Phase 2 对照正典时用它定位
AGENTS.md / CLAUDE.md。

据此定范围（范围规则全部在此，别处不再定义）：

- **默认**（用户只说 /deep-memoir）：处理所有近 N 天有会话的项目，N 默认 7。
- **用户带范围时收窄**：「整理当前项目」→ 只处理当前工作目录对应项目；
  「只整理 X」→ 点名项目；「排除 X」「别动公司项目」→ 从默认名单剔除；
  「最近一个月」等时间词 → 换算 `--days`。
- **候选新建**：有近期会话但无 memory 目录的项目，列入报告等确认。
- **跳过**：无近期活动的项目，报告末尾列名单；用户点名时再处理。

完成标准：一份明确的处理名单（含候选新建与跳过名单）。

## Phase 2 — Gather Signal（采集信号，产出：逐项目信号清单）

对名单中每个项目，读三样东西——记忆、正典、对话：

1. 读该项目 `memory/MEMORY.md` 与全部条目文件。
2. 读该项目仓库（`path` 列定位）的 AGENTS.md / CLAUDE.md（如存在），
   作为正典对照基准。
3. 提取近期会话中的真实用户输入（脚本已过滤命令回显与工具结果；
   项目目录名以 `-` 开头，`--extract` 必须用 `=` 连接）：

```bash
python3 scripts/gather.py --extract=<project-dir> --days 7
```

在用户输入中找四类信号：

- **纠正**：用户否定或修正了 Claude 的做法（「不对」「改成…」）
- **拍板决策**：被明确定案的方案、约定、边界（「就这样」「以后都…」）
- **偏好**：反复出现的工作方式、工具选择、表达习惯
- **过时**：与现有 memory 条目矛盾的新事实、已完成的「进行中」事项、
  失效的相对日期、**已被正典覆盖的既有条目**

完成标准：每个项目都有一份信号清单（可以为空，但必须过完四类），
且既有条目已逐条与正典比对过。

## Phase 3 — Consolidate（起草报告，产出：等待确认的整理报告）

**入库门槛**：拟新增只收两类最高信号——**纠正**与**拍板决策**（反复
出现并被用户以行动确认的偏好视同拍板）。单次出现的表述、仍在探索中的
话题不入库——真正重要的事会再次出现，留给下次做梦收。

**状态核对标注**：transcripts 只反映会话结束时刻的世界，此后用户自己
推进的事模型不知道。凡记录「进行中/待办/报错」等状态的条目，在报告中
标注 ⚠️「状态可能已变化，请核对」，提醒用户重点确认。

按项目分节汇总，每条操作附证据（哪天的会话、用户原话摘录）：

```markdown
## <项目名>
### 拟新增
- `<slug>.md`（type: feedback）—— <一句话内容>。依据：<日期>「<原话摘录>」
### 拟更新 / 拟合并
- <文件>：<改什么、为什么>
### 拟删除
- <文件>：<过时 / 与 <正典文件> 重复 的理由>

## 候选新建 memory 的项目
- <项目名>：<值得沉淀的内容概要>

## 本次跳过
- <项目名>（无近期活动）…
```

无变化的项目写一行「无需调整」。完整展示报告后停下，等用户确认——
可整体确认、点名部分执行或要求修改。

完成标准：报告覆盖名单中每一个项目，且已获得用户的明确答复。

## Phase 4 — Prune & Index（写入与重建索引，产出：变更统计）

仅执行用户确认的操作：

1. 按报告新增/更新/合并/删除。条目文件保持既有 frontmatter 格式
   （`name` / `description` / `metadata.type: user|feedback|project|reference`），
   相对日期转绝对日期，相关条目用 `[[name]]` 互链。
2. 重建每个改动项目的 `MEMORY.md`：一行一条
   `- [标题](文件.md) —— 钩子句`，只放索引不放正文。
3. 汇报：每个项目新增/更新/合并/删除条数，跳过项目数。

完成标准：确认过的操作全部落盘，索引与条目一致，统计已汇报。
